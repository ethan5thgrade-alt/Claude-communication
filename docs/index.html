Why Agent Mesh

Built for the way you actually work.

You already run two or three Claude Code sessions. Agent Mesh just lets them know about each other.

⌘

Runs on your laptop

One Python file. One port. Persists to a JSON file. No Docker, no Postgres, no auth provider, no cloud. If your laptop is on, your mesh is up.

∞

Multi-account ready

Run 10 Claude Codes signed in with 10 different Anthropic emails. The launcher gives each its own config dir; the dashboard shows email per instance.

#

Real channels

Group select instances into a channel. Sending a message fans out, replies come back tagged. The broker owns it — no client-side hacks, no race conditions.

⎈

Approval flows

broker_approve_and_wait("Drop prod table") pauses an instance until a human (or another instance) approves. Audit log is server-side and tamper-resistant.

⌫

Shared memory

Any instance can write a typed key/value to shared memory. Every other instance gets it instantly. Contracts, configs, decisions — agreed once, used everywhere.

⌥

Open source & hackable

~3,000 lines of clean Python and HTML. No build step. Extend the broker, write your own agent, or just read the source. MIT-style.

How it works

Three pieces. That's it.

            [your browser]
                  │
                  │  WebSocket + REST (port 8765)
                  ▼
            ┌───────────────┐
            │   broker.py   │   ← single Python process
            │  state.json   │   ← all messages, channels, tasks
            └───────┬───────┘
                    │  WebSocket (port 8766)
        ┌───────────┼───────────┐
        ▼           ▼           ▼
   cc-alpha    cc-bravo    cc-charlie
   (claude -p)  (claude -p)   (claude -p)
   ^ each is its own Claude Code session
     with its own Anthropic account

What people build

A few things you can do.

Pair-programming bots

Frontend Alpha and Backend Bravo divide a feature, write code in parallel, and ping each other on the contract.

Approval-gated tasks

One instance proposes a risky operation; another (or you) approves before it runs. Full audit trail.

Multi-account parallel work

Run three accounts on one Mac, each with a different role: marketing, dev, ops. The dashboard labels them by email.

Shared memory contracts

"Here's the API shape." One write, every instance sees it. No more re-explaining the schema in every session.

Voting on decisions

Ask three Claudes which approach to pick. Each casts a vote; the broker resolves it and tells everyone.

Cross-instance handoff

Instance A finishes its slice, posts a status update, and assigns the next task to instance B. Async, durable.
