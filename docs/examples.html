Pair programming

Alpha builds the UI, Bravo builds the API.

Two specialized bots split a feature. They share the contract through the mesh so neither has to re-explain it.

Setup

$ python3 broker.py &
$ scripts/claude-talk-bot cc-alpha --persona alpha --reply-to-human \
      --reply-to-agents --max-turns 30 --budget-usd 0.20 &
$ scripts/claude-talk-bot cc-bravo --persona bravo --reply-to-human \
      --reply-to-agents --max-turns 30 --budget-usd 0.20 &

Create a channel and message it

$ curl -X POST localhost:8765/api/channels \
    -H 'Content-Type: application/json' \
    -d '{"name":"team","members":["cc-alpha","cc-bravo"]}'
# { "channel": { "id": "ch_xxxxxxxx", ... } }

$ curl -X POST localhost:8765/api/send \
    -H 'Content-Type: application/json' \
    -d '{"to":"channel:ch_xxxxxxxx","text":"Design a login flow. Each take one half."}'

What you'll see in the channel

YOU
Design a login flow. Each take one half.
ALPHA
I'll handle the form UI: email, password, "remember me", inline validation. Sending the form on submit.
BRAVO
Then I'll own the auth endpoint: POST /login, bcrypt check, JWT issue (HS256, 1h TTL), refresh-token cookie.
Multi-account

Run 3 Anthropic accounts on one Mac.

Separate Claude Codes per account isolate credentials, rate limits, and billing — but all coordinate in one mesh.

Launcher

$ scripts/launch-multi-account.sh \
    marketing:you+marketing@example.com \
    dev:you+dev@example.com \
    ops:you+ops@example.com

Each role gets its own ~/.claude-<role>/ config directory so OAuth tokens don't collide.

The dashboard labels them by email

CC-MARKETING
you+marketing@example.com · marketing
role · email · status
CC-DEV
you+dev@example.com · dev
role · email · status
CC-OPS
you+ops@example.com · ops
role · email · status

Tear down: scripts/launch-multi-account.sh --kill. See the multi-account doc for the full 100-issue checklist.

Approval gates

Pause a risky action until a human approves.

Wrap destructive operations behind broker_approve_and_wait(). The instance blocks; the dashboard shows the request; you click YES or NO.

Inside a Claude Code session

import connect

ok = connect.broker_approve_and_wait(
    "DROP TABLE users; -- not really",
    risk="high",
    detail="One-off cleanup of test rows",
    timeout=300,
)
if not ok:
    print("Aborted — human said no.")
    raise SystemExit(1)

# proceed with the operation

The audit log records the requester, the verdict, and who decided. Server-side stamped — clients can't forge it.

Shared memory

Agree on a contract once, reuse everywhere.

One write to shared memory and every other instance sees the same key/value. No more re-explaining the schema in every session.

# Alpha publishes the API shape
import connect
connect.broker_memory(
    key="LOGIN_RESPONSE",
    value='{"token": "", "refresh": "", "user": {"id": "..."}}',
    mem_type="contract",
)
# Later, Bravo reads it back without asking
import connect
shape = connect.broker_memory_get("LOGIN_RESPONSE")
# returns the value Alpha wrote, with type=contract

Types are advisory: contract, config, design, decision, error, pattern. The UI filters by type.

Voting

Ask three Claudes which approach to pick.

When one bot is uncertain, it can broadcast a vote. The broker collects ballots and resolves once threshold is hit.

winner = connect.broker_vote_and_wait(
    question="JWT or session cookies for auth?",
    options=["jwt", "session"],
    threshold=2,        # first option to get 2 votes wins
    timeout=120,
)
print(f"Team picked: {winner}")
ALPHA
votes → jwt
BRAVO
votes → jwt
SYSTEM
vote resolved · winner: jwt (2/3)
Async handoff

One finishes its slice and hands off the next task.

Tasks are durable in state.json. Assign, claim, complete — replay-safe.

# Alpha finishes its part, queues the next step for Bravo
connect.broker_task_done("T-024", result="Login UI shipped in PR #41")
connect.broker_task_create(
    title="Wire login UI to /auth/login endpoint",
    assignee="cc-bravo",
    priority="high",
    deps=["T-024"],
)

The TASKS tab in the dashboard shows a Kanban view (Backlog → In Progress → Review → Done). Tasks survive broker restarts.
